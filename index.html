SYSTEM VULNERABILITIES DETECTED

Standard command-line interfaces present critical security risks in shared environments :

  • UNRESTRICTED ACCESS: Bash/Zsh grant users full execution privileges by default, allowing arbitrary process kills .
  • ZERO AUDITABILITY: Standard shells lack persistent tracking . Incident forensics are severely compromised without an immutable log .
  • BINARY PRIVILEGE MODEL: The native UNIX permissions model lacks intermediate privilege levels (User vs. Root) .

THE COUNTERMEASURE (OBJECTIVES)

Deployment of a custom C-based shell engineered for absolute execution control .

  • COMMAND WHITELISTING: Default Deny architecture. If the binary is not explicitly permitted, execution is aborted .
  • RBAC PROTOCOL: Role-Based Access Control enforcing dynamic command environments based on current user assignment .
  • AUDIT LOGGING: Persistent command audit log that records each command attempt, including timestamp and outcome .

SCOPE & BOUNDARIES

To isolate core OS security paradigms, advanced scripting functionalities were intentionally excluded :

[ IN SCOPE ]

- Input tokenization

- Configurable Whitelists

- Background Job Tracking

- Persistent logging

[ OUT OF SCOPE ]

- Shell scripting (loops/if-else)

- Environment variables ($PATH)

- Complex pipe chains

- Full POSIX compliance

PIPELINE ARCHITECTURE

Applying the OS principle of Separation of Responsibilities .

  • main.c : Coordinates modules and runs the read-eval-print loop .
  • parser.c : Tokenizes input into an argument array without checking permissions .
  • acl.c : The Policy Engine. Manages whitelist tables and validates commands .
  • logger.c : Writes structured log entries (timestamp, role, command, result) .
  • executor.c : Process Engine. Never checks ACL; blindly executes if passed .

ASYNCHRONOUS EXECUTION (&)

Handling background processes to maintain terminal interactivity .

  • DETECTION: The parser detects the trailing & operator during tokenization .
  • NON-BLOCKING PARENT: If background execution is requested, the parent process skips the immediate waitpid() call .
  • JOB TRACKING: The child process PID is appended to the active jobs array, verifiable via the built-in jobs command .

POSIX SYSTEM CALLS

Direct interfacing with the OS kernel :

  • fork() & execvp() : The backbone of process creation. The shell duplicates itself, replacing the child image with the authorized binary .
  • waitpid() : Blocks the parent shell until the foreground child terminates to prevent zombie processes .
  • time() & fopen() : Constructs immutable temporal records for the persistent audit file .

AUDIT LOG OUTPUTS

Intercepting unauthorized processes before memory is allocated .

[secshell]$ ls -la
2026-03-26 14:02:11 | ROLE: user | CMD: ls -la | STATUS: ALLOWED

[secshell]$ shutdown now
2026-03-26 14:02:35 | ROLE: user | CMD: shutdown now | STATUS: BLOCKED
[BLOCKED] Command 'shutdown' is not permitted for role 'user'.

DESIGN TRADE-OFFS

  • C vs. Python : C provides direct access to POSIX system calls without abstraction layers, making the relationship between shell code and OS behavior explicit .
  • Static Arrays vs. Config Files : Whitelists are statically compiled in Phase 2 to ensure correctness during early development .
  • Local File vs. Syslog : Audit logs are written locally (audit.log) to maintain project portability instead of hooking into system daemons .

SYSTEM SECURE

By implementing command whitelisting, role-based access control, and audit logging in C, the project bridges the gap between theoretical OS principles and practical system-level programming .
